## 1. 一句话 / 三句话 / 电梯演讲

### 一句话
> **DataAgent 让企业用自然语言问数据，但大模型从头到尾没有写过一行 SQL——
> 它只能填一张受严格约束的"表单"，SQL 由一段纯函数代码确定性生成。**

### 三句话
1. **怎么做**：自然语言 → 契约 DSL（JSON）→ 确定性编译器 → SQL → DuckDB。
2. **为什么这么做**：模型幻觉、越权、SQL 注入这三类问题，
   在"模型产 SQL"的架构里是**治不好的概率问题**；
   在"模型产 DSL"的架构里是**结构上不可能**。
3. **效果**：678 个测试全绿、25 道 golden 评测 oracle 模式 23/25 通过、全链路四层安全防线。

### 电梯演讲（30 秒）
> "企业里业务方想查个数，得走'提需求 → 分析师写 SQL'，延迟是天级。
> 用大模型直接写 SQL 呢？快是快了，但**它会把字段名编错、会忘了加权限过滤、
> 可能被一句提示词注入就泄露全公司数据**。
>
> 我的做法是：**不让模型写 SQL，让它填一张受约束的表单**——
> 字段名必须来自已登记的语义目录，聚合方式只能是六种之一，
> 表单之外的任何字段一律拒绝。
>
> 然后由一段纯函数代码把表单编译成 SQL，
> 并且在编译之后、执行之前**强制注入权限过滤**——
> 无论表单长什么样，最终 SQL 里一定有那一段。
>
> **聪明的事交给模型，正确的事交给代码。**"

## 3. 架构速记（六层 + 十一关）

```
L1 交互层    Web UI / SSE 流式 / 4 个演示账号
L2 编排层    六节点 StateGraph：clarify→plan→query→analyze→critique→synthesize
L3 智能层    意图路由(6类) / NL→DSL / 多轮记忆 / 澄清回填 / ToolAgent
L4 语义与编译层  semantic/catalog.py(SSOT) → QueryDSL(extra=forbid) → sql_compiler(纯函数)
L5 执行与治理层  exec/guards.py(四层只读 + 三保险丝) + exec/audit.py(执行前审计)
L6 存储与沙箱层  DuckDB(只读) + Parquet 物化 + 沙箱(AST守卫 + Docker/子进程)
```

**铁律**：`orchestrator → retrieval/sandbox/skills/agent`；
`retrieval` 不依赖 `orchestrator`；`sandbox` 不感知业务语义；`skills` 只依赖 numpy + 标准库。

**11 道安全关卡**（按执行顺序）：
1. 认证网关 → 2. principal 服务端绑定 → 3. 意图路由拦截 →
4. 生成前作用域收窄 → 5. 裸 SQL 网关 → 6. 契约校验 →
7. 权限守卫（表/列/行）→ 8. 编译器字面量转义 → 9. 执行前审计 →
10. 只读四层校验 → 11. PII 脱敏导出

## 4. 五个查询形态（编译器分支）

| 形态 | DSL 字段 | 生成什么 | 关键点 |
| --- | --- | --- | --- |
| **普通聚合** | `metrics` + `dimensions` | `SELECT ... GROUP BY ...` | 维度为空则清 `order_by` |
| **同环比** | `comparison: yoy/mom` | `cur` / `prev` 两个 CTE | `(cur-prev)/NULLIF(prev,0)` |
| **分组 Top-N** | `top_n: {n, partition_by, order_by}` | `ROW_NUMBER() OVER (PARTITION BY ...)` + 外层 `WHERE __rn <= n` | 校验 partition 是维度、order_by 是别名 |
| **日期补零** | `fill_gaps: true` | `__spine` CTE（`generate_series`）+ `__agg` CTE + `COALESCE` LEFT JOIN | 需时间维度**且唯一** + 明确 `time_filter` |
| **窗口指标** | `WindowMetric(cumsum/moving_avg)` | `SUM/AVG(...) OVER (ORDER BY ... [ROWS BETWEEN n-1 PRECEDING AND CURRENT ROW])` | **不能与 comparison/top_n/fill_gaps 混用** |

## 5. 三个主体权限矩阵

| 主体 | 可访问表 | 禁止列 | 行过滤 |
| --- | --- | --- | --- |
| `admin` | 全部 5 张 | — | — |
| `analyst` | 全部 5 张 | — | `province IN (广东,浙江,江苏,北京,上海)` |
| `bob`（restricted） | `dim_product` / `dim_user` / `fact_orders` | `discount_amount` / `refund_amount` | `province IN (广东)` |

**`bob` 的实测 SQL**：
```sql
SELECT SUM(f.order_amount) AS "gmv"
FROM fact_orders f JOIN dim_user u ON u.user_id = f.user_id
WHERE f.pay_status = 'SUCCESS'
  AND u.province IN ('广东')                    ← 强制注入，无法绕过
  AND f.order_time >= TIMESTAMP '2024-06-01 00:00:00'
  AND f.order_time <  TIMESTAMP '2024-07-01 00:00:00'
```

## 6. 十句金句（紧张时看这一节）

1. **"聪明的事交给模型，正确的事交给代码。"**
2. **"能让它做不到，就不去检查它有没有做。"**
3. **"别让模型写 SQL，让它填一张表单。"**
4. **"契约不是'请模型遵守'，是'模型说了不算'。"**
5. **"权限靠注入，不靠检查。你写什么，我都会 AND 上那一条。"**
6. **"响亮地失败，永远好过安静地放行。"**（fail-closed）
7. **"安全系统的默认值必须是'关'。"**
8. **"一个数据分析系统最危险的输出不是'我算错了'，而是'我很自信地告诉你一个没有依据的结论'。"**
9. **"评审报告的价值在于它记录了什么，不在于它给了多少分。"**
10. **"一个工程师最重要的能力，不是'能做出什么'，而是'知道自己做的东西在什么位置'。"**

**技术类金句（追问时用）**：
- "编译器的报错必须精确，**因为它是模型的修正信号**。"
- "注入和剥离必须是一对函数，**有几次注入就必须有几次剥离**。"
- "任何'重新构造对象'的路径，都可能丢失之前施加在对象上的约束。"
- "降级方案最常见的失败模式是**假装自己很强**。"
- "成本控制不是优化出来的，是**设计出来的**。"
- "模型能力越强，**刹车系统的价值越高而不是越低**。"

## 7. 五个知名"坑"（面试官问缺陷时主动说）

| 坑 | 现象 | 我的处理 |
| --- | --- | --- |
| **标量同环比被审计拒绝** | 无维度的 MoM 查询生成 `FROM cur, prev`，被判笛卡尔积 | **已知限制，故意没随手改**——"放宽审计"和"改编译器"之间要有测试保护的选择 |
| **连接池双份** | `web/service.py` 和 `exec/pool.py` 各一个池，并发上限被软性破坏 | 已定位，列为上线前整改项：统一到 `exec/pool.py` 单例 |
| **SSE 运行状态在进程内** | 多实例部署无法共享、重启丢失未完成编排 | 正确做法是事件流外置到 Redis Stream / Kafka |
| **契约无版本号** | 改契约会让学生历史 DSL（记忆/审计里的）失效 | 应加 `schema_version` + 迁移函数 |
| **无行覆盖率统计** | 说得出测试数，说不出覆盖率 | 诚实承认；测试策略是"关键路径 + 安全边界"而非覆盖率数字 |

## 9. 三句"不确定时"的缓冲话术

被问到不会的东西时，**不要硬答，用这三句之一争取思考时间**：

1. **"这个问题我要分两层回答，先说结论，再说理由。"**
   （给自己 3 秒组织语言）

2. **"我先说我知道的部分，然后说我不确定的部分。"**
   （诚实 + 有结构）

3. **"这个我没有实测数据，我的判断是 X，理由是 Y——如果错了请指出来。"**
   （把不确定变成可验证的假设）

**绝对不要说的三句**：
- ❌ "应该是……吧"（听起来没底气）
- ❌ "这个我们没考虑"（听起来不专业，改成"这个我们决策为暂不支持"）
- ❌ 编一个数字（**一追问就穿帮，代价最大**）
