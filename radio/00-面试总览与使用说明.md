### 1.2 三条记忆主线

准备面试最怕"知识点散"。这套材料的全部内容可以挂在三条主线上：

```
主线 A（为什么可信）：LLM 只产 DSL，SQL 由确定性编译器产出
主线 B（为什么安全）：生成前约束 → 生成后校验 → 执行层熔断，三层纵深
主线 C（为什么是 Agent）：图式编排 + 沙箱分析 + 归因技能包，从"问数"到"给结论"
```

任何一道题答不上来时，先回到这三条主线找位置——绝大多数追问都是主线的分支。

### 1.3 诚实原则（重要）

本材料刻意保留了三类"不好看但真实"的内容，**面试时不要回避**：

1. **基准评测曾判 FAIL（69 分）**——当时 6 个维度里"透明度与解释性"只有 45 分。这不是耻辱，而是你展示"工程复盘能力"的最好素材。
2. **当前仓库配置的唯一模型供应商订阅失效**（返回 `InvalidSubscription`）——这是**环境**问题不是**代码**问题，讲清楚这个区别本身就是加分项。
3. **文档里的测试数字滞后**（`README.md` / `docs/quality.md` 写 622 个用例）——我实测是 **678 passed**。面试官如果翻文档，你能主动指出来，反而是细心与诚实的证据。

## 二、项目一句话与三句话

### 2.1 一句话（电梯陈述）

> DataAgent 是一个**企业级数据分析智能体**：用户用大白话提问，它在受控契约下自动完成"理解问题 → 取数 → 分析 → 写报告"，而**大模型从头到尾没有机会写出一行 SQL**。

### 2.2 三句话（展开版）

1. **问题**：让大模型直接写 SQL 做数据分析，会幻觉字段、会越权、会写出删表语句，企业不敢用。
2. **做法**：我们把模型关进契约的笼子里——它只能产出一个受严格校验的 JSON（我们叫 DSL），SQL 由一段**完全确定性的编译器**生成，跑之前还要过只读白名单、笛卡尔积审计、超时与扫描行数熔断。
3. **价值**：换来的是**零幻觉、零注入、零随意 Join**，以及一个可审计、可复现、可单测的数据分析链路。

## 三、仓库事实速查（面试官可能当场翻代码）

```
D:\Program\DataAgent\
├── semantic/       语义目录 + DSL 契约（单一事实来源 SSOT）
├── compiler/       DSL → SQL 确定性编译器（811 行，核心资产）
├── agent/          NL→DSL Agent、意图路由、工具调度、会话记忆、槽位回填
├── exec/           SQL 执行治理：只读 AST 校验 / 超时看门狗 / 扫描熔断 / 执行前审计
├── security/       表级 / 列级 / 行级 RLS + 生成前作用域
├── core/
│   ├── orchestrator/  StateGraph 六节点编排（零框架自研）
│   ├── retrieval/     取数门面 + PII 脱敏 + 裸 SQL 网关 + 动态 profiling + DataQA
│   ├── sandbox/       代码解释器：AST 守卫 + 限权 runner + Docker/子进程后端
│   └── skills/        归因技能包：熵下钻 / 分解树 / DTW / Holt-Winters / Shapley
├── tools/          工具注册中心 + 4 个内置工具
├── providers/      多模型供应商网关（四协议 / Key 加密 / 请求级切换）
├── auth/           JWT + Session 认证、PBKDF2 口令、登录限流
├── audit/          审计快照 + 结构化 JSON 日志 + 进程内指标
├── present/        中文解释 + 图表推荐（确定性规则）
├── web/            Web 服务 + SSE 流式 + 原生 JS 工作台（零前端框架）
├── mock/           确定性 mock 数仓（DuckDB，种子 42）
├── eval/           Golden 评测（25 用例，含多轮序列）
└── docs/           文档 + 历次评审归档
```

**关键锚点**（能背下来非常加分）：

- 数据基准日 `AS_OF_DATE = 2024-06-30`，随机种子 `42`；
- mock 数仓规模：`fact_orders=3000` / `fact_refunds=341` / `dim_user=200` / `dim_product=60` / `dim_shop=20`；
- 编译器文件 `compiler/sql_compiler.py` 811 行，是"确定性"这条主线的物理落点；
- 执行层超时 `QUERY_TIMEOUT_MS=30000`、扫描上限 `MAX_SCAN_ROWS=10000000`、结果上限 `MAX_RESULT_ROWS=20000`。
