## S1 语言与运行时

| 候选 | 数据/AI 生态 | 团队与运维 | 结论 |
|------|-------------|-----------|------|
| **Python 3.11+（环境锁定 3.12）（选定）** | pydantic/pandas/numpy/sqlglot/DuckDB 生态一等公民 | conda 环境管理、pytest/black/ruff 质量门齐备 | ✅ 规格驱动 + LLM 编排 + 数据分析三者皆 Python 主场 |
| Node.js/TypeScript | SQL 与数值生态弱（DuckDB 绑定次优） | — | ❌ 分析引擎与评测链路生态劣势 |
| Go/Java | 需自建 LLM/数据工具链 | — | ❌ 交付速度与生态不匹配 |

## S2 DSL 契约层

| 候选 | 校验强度 | 错误消息质量 | 结论 |
|------|---------|-------------|------|
| **Pydantic V2，`extra="forbid"` 全模型（选定）** | 强类型 + 契约内字段封闭 | 精确字段级报错，可直接喂 LLM 自愈 | ✅ "Agent 只能产出契约内字段"铁律的语言级保证 |
| JSON Schema（jsonschema 库） | 校验等价 | 报错偏薄 | ❌ 自愈回路消息质量差 |
| 手写校验器 | 自由 | — | ❌ 维护成本高、覆盖漂移 |

## S3 分析引擎（本地数仓）

| 候选 | 分析能力 | 运维面 | 结论 |
|------|---------|--------|------|
| **DuckDB（选定）** | 列式 OLAP、窗口/generate_series 原生、单文件零部署 | 进程内嵌入，零服务 | ✅ 分析型问数的最优零运维解；EXPLAIN ANALYZE 支撑扫描熔断 |
| SQLite | 行式、窗口函数弱 | 零 | ❌ OLAP 能力不足 |
| PostgreSQL/MySQL 直连 | 强 | 需常驻服务与部署 | ❌ 与"本地零运维数仓"定位冲突（后续作为**执行后端**接入是另一决策，见二十一期起） |
| pandas 内存计算 | 中 | 零 | ❌ 数据规模与 SQL 语义覆盖不足 |

## S4 NL → SQL 的编译形态

| 候选 | 幻觉/注入面 | 可审计性 | 结论 |
|------|------------|---------|------|
| **LLM 产 DSL(JSON) → 自研确定性编译器产 SQL（选定）** | LLM 永不触 SQL | DSL 契约可校验、SQL 可逐字节 golden 锚定 | ✅ 架构核心铁律：从根源杜绝幻觉 SQL 与注入 |
| LLM 直出 SQL | 不可控 | 不可锚定 | ❌ 触碰非妥协红线 |
| sqlglot 由语义结构生成 SQL | 可控 | 部分可锚定 | ❌ 与确定性编译器职责重叠，转译产物语义漂移（二十一期 D4 复评维持否决） |

## S5 SQL 静态审计/解析

| 候选 | 方言覆盖 | 绕过抗性 | 结论 |
|------|---------|---------|------|
| **sqlglot AST（read=方言）+ 方言增量黑名单（选定）** | 多方言统一 | 结构化解析，引号/别名/嵌套绕过免疫 | ✅ 护栏四层结构（语句黑名单/函数黑名单/AST/方言增量）的核心 |
| sqlparse | 解析浅 | 弱 | ❌ 无方言转译与 AST 语义 |
| 纯正则黑名单 | — | 可被引号/注释绕过 | ❌ 已被 AST 方案取代（渗透测试实锤先例） |

## S7 认证体系

| 候选 | 撤销能力 | API/页面双场景 | 结论 |
|------|---------|---------------|------|
| **JWT + Session 双轨 + 登录限流（选定）** | Session 服务端可撤销 | API 用 JWT、页面用 Session | ✅ 双场景各取所长，限流共享持久化 |
| 纯 JWT | 撤销需黑名单基础设施 | — | ❌ 撤销语义弱 |
| 纯 Session | 强 | API 客户端不便 | ❌ 工具型 API 场景受限 |

## S10 前端形态

| 候选 | 构建链 | 交互复杂度承载 | 结论 |
|------|--------|---------------|------|
| **原生 JS + SSE + vendored ECharts/PrismJS（零前端框架）（选定）** | 零构建 | 时间线/审批卡/画布自研 | ✅ 零依赖哲学延伸到前端；交付与维护成本最低 |
| React/Vue + 组件库 | 需 node 构建链 | 组件化 | ❌ 引入构建链与依赖审计面，收益不匹配 |

## S11 评测机制

| 候选 | 确定性 | 回归能力 | 结论 |
