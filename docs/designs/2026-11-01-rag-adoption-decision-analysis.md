# 设计分析｜RAG 知识库引入决策（2026-11）

> - **状态**：**暂不立项（2026-11-01）**。本篇是讨论分支 `discuss/dev-iteration` 上的
>   决策分析落盘，回答两个问题，一是 DataAgent 现阶段是否需要检索增强生成
>   (Retrieval-Augmented Generation, RAG)，二是将来什么条件下值得立项。
>   触发条件见 §三，届时形态见同节，架构红线见 §四。

## 一、背景与结论

能力盘点（2026-11-01）将知识库检索列为待评估缺口之一。本文是对该缺口的决策分析，
结论如下。

**现阶段不立项，且将来立项时也不应采用"外挂文档知识库"的形态。** RAG 要解决的问题
本项目当前不存在，而它会引入的问题（业务事实双来源、概率性上下文污染）恰好是架构
过去二十五期在消灭的。建议在缺口清单中标注"目录规模触发再评估"，而非现在动手。

## 二、为什么现阶段不做

### 2.1 规模不成立

RAG 的第一动机是上下文经济性，即元数据与知识多到全量注入装不下，才需要检索收窄。
实测 `config/semantic.json`（2026-11-01），全目录 60 个字段、6 张事实表、7 个指标，
另有别名、连接规则、口径等小节，量级极小。全量注入 prompt 绰绰有余，检索没有收益，
只有风险与链路复杂度。

### 2.2 单一事实源铁律

M-P2 语义去耦确立了 `config/semantic.json` 是唯一静态业务事实源（见
[语义去耦设计](2026-10-07-semantic-decoupling-design.md)）。RAG 文档库天生构成
第二事实源。文档与目录口径一旦漂移，检索命中的就是过时口径，且这种污染是静默的，
无报错、无告警、难审计。近期提交 03f26d8 刚消灭"维度成员双来源导致的不确定性"，
方向上刚完成去双来源，不应反向再引入一个。

### 2.3 确定性哲学冲突

架构根基是 LLM 只产契约受控 DSL，事实一律来自语义目录。RAG 是概率性注入，
检索错等于上下文错。真出现脏注入，编译器能拦住目录外字段（fail-closed 守门在），
但拦不住口径叙述被带偏，这与"诚实等于不虚构加假设透明"的原则直接相悖。
污染还会顺着 Planner 进入 DSL，事后无从区分是模型幻觉还是检索带入。

### 2.4 瓶颈错位

当前真实痛点是 LLM 供应商稳定性与时延（流式改造、握手期超时预算均为此服务，见
[握手重试设计](2026-10-05-llm-handshake-retry-design.md)）。知识检索不是短板，
现在投入不解决任何已观测到的问题。

## 三、何时值得做（触发条件）

满足任一条件再立项，且届时形态依条件而定。

### 触发条件一，目录规模爆炸，做语义目录检索化

接入真实企业规模目录（数百表、数千字段）时，全量注入不可行。届时做的是语义链接
(schema linking)，按 FieldMeta 粒度建向量索引，召回结果只是目录条目的引用。
这是结构化检索，不是文档 RAG。

建议量化锚点（预估值，立项时按实测校准）。全量目录注入估算超过 Planner 上下文
预算的三分之一，或字段数超过 300，触发本条件复核。

### 触发条件二，示例检索提准，做 golden 少样本检索

eval golden 已有 31 条问句到 DSL 的配对。按问句相似度取 top-k 注入 Planner 作
少样本提示 (few-shot prompting)，可提升 DSL 一次编译成功率。索引对象是自家
金标对，不含业务事实，无漂移风险，是 RAG 形态中唯一与架构零冲突的。
此条件与目录规模无关，若 Planner 一次编译成功率实测偏低，可独立先行。

### 触发条件三，业务文档问答成为产品需求

出现"对着业务文档问答"的真实需求时，做成独立功能面，严禁接入 DSL 管道，
取数权照旧只在执行层。文档问答的结论不得反哺语义目录口径，口径变更必须走
`semantic.json` 正常登记流程。

## 四、真做时的架构红线

无论哪种形态，以下约束不可破。

1. **检索只许收窄，不许新增事实。** 召回结果只能是目录内条目或 golden 示例的引用，
   禁止携带目录外字段，编译器守门不变；
2. **检索失败不阻塞主链路。** 目录小时检索异常回退全量注入，不允许因检索故障
   导致取数不可用；
3. **依赖方向单向。** 落点在 `agent/` 侧规划上下文增强，检索器只依赖
   `semantic/catalog`，不得反向，不得感知编排状态。

## 五、决策记录

| 事项 | 结论 |
|------|------|
| 现阶段是否挂 RAG | 否，暂不立项（2026-11-01） |
| 立项形态 | 条件一对应语义目录检索化；条件二对应 golden 少样本检索；条件三对应独立功能面 |
| 复核时点 | 接入真实企业规模目录时；或 Planner 一次编译成功率需要提升时 |
| 缺口清单动作 | 标注"目录规模触发再评估"，移出主动待办 |
